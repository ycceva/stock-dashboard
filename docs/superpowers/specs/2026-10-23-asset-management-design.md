# 우리집 자산관리 페이지 — 설계서

작성일 2026-10-23 · 대상 저장소 `ycceva/stock-dashboard` (GitHub Pages, 로컬 `~/Claude/stock-dashboard`)

## 1. 왜 만드나

사용자는 한 달에 한 번 집안 자산(부동산 시세, 본인·배우자 계좌 잔액)과 그달 입금·지출을 직접 적는다. 이 기록을 모아서 다음을 한 화면에서 보려는 것이다.

- 지금 총자산이 얼마인지
- 그중 쓸 수 있는 현금은 얼마인지
- 지난달보다 얼마나 늘었는지
- 은퇴 목표 현금 20억에 얼마나 다가갔는지

여기에 Claude가 20년 차 은퇴설계 전문가 입장에서 분석과 짧은 조언을 덧붙인다. 지금 쓰는 주식 대시보드(로그인해야 볼 수 있음) 안에 붙여서, 같은 로그인으로 부부가 함께 본다.

## 2. 목표 / 하지 않을 것

**목표**
- 매달 팝업 하나에서 그달 숫자를 모두 입력·수정할 수 있다.
- 첫 화면에서 총자산, 현금, 부동산, 전달 대비 증감, 은퇴준비율을 바로 읽을 수 있다.
- 부동산이 총자산의 80~90%라도 현금 구성이 잘 보인다.
- 데이터를 백업하고 복원할 수 있다.

**하지 않을 것**
- 은행·증권사 자동 연동, 시세 자동 조회. 숫자는 모두 사람이 직접 넣는다.
- 은퇴 시점, 나이, 지출 항목별 금액 입력. 은퇴준비도는 "20억 중 현재 현금 몇 %"만 보여준다.
- 페이지 안에서 AI API 호출. AI 점검은 Claude가 대화에서 쓴다(6.6 참고).

**실패로 볼 것 (돌아가더라도)**
- 로그인하지 않은 사람이 자산 숫자를 볼 수 있는 경우. 사이트는 GitHub Pages로 공개돼 있으므로 데이터는 반드시 로그인 뒤에만 읽혀야 한다.
- 입금·지출을 총자산 계산에 넣는 경우. 둘은 기록용일 뿐이다.

## 3. 용어와 계산 규칙 (사용자가 정한 것)

| 항목 | 정의 |
|---|---|
| 현금 | 총자산 − 부동산. 본인·배우자의 모든 계좌 잔액 합(주식, 연금, CMA 포함) |
| 총자산 | 부동산 시세 + 본인 계좌 합계 + 배우자 계좌 합계 |
| 이달 입금 / 이달 지출 | 월급과 지출 기록. **총자산·현금 계산에 들어가지 않는다.** 그 결과는 사용자가 계좌 잔액에 직접 반영해서 입력한다 |
| 은퇴준비율 | 현금 ÷ 20억 × 100 (%) |
| 목표 은퇴현금 | 20억 고정. 월생활비, 의료비, 여행비, 취미·운동비, 세금, 기타 비상금을 예상한 금액이다. 항목은 이름표로만 보여주고 금액 입력은 받지 않는다 |
| 전달 대비 | 이번 기준월 총자산 − 바로 이전에 기록된 달의 총자산 (금액과 %) |

"기준월" = 기록된 달 중 가장 최근 달. *(설계자 판단)* 바로 이전 달 기록이 비어 있으면 그 앞의 가장 최근 기록과 비교하고, 비교한 달을 작게 표시한다. 기록이 하나뿐이면 "—"로 둔다.

## 5. 자산관리 페이지 (`assets.html`) 전체

- 새 파일 `assets.html`. 기존 `index.html`과 같은 Supabase 프로젝트와 로그인 세션을 쓴다. 로그인 안 된 상태로 들어오면 대시보드와 같은 로그인 화면을 보여주거나 `index.html`로 돌려보낸다.
- 다크 모드. 대시보드와 같은 톤(배경 #141414, 글자 #e2e2e2, 섹션 카드는 한 단계 밝은 회색)을 쓴다.
- 금액 표시는 한국식 단위로 한다(예: "12억 8,000만", "1,800만"). *(설계자 판단)* 입력은 원 단위 숫자에 천 단위 콤마를 자동으로 넣는다.
- 상단 바: "← 대시보드" · 제목 "우리집 자산관리" · "⬇ 백업" · 노란 "✎ 이번달 가계부쓰기".
- 기록이 하나도 없으면 각 섹션에 "이번달 가계부쓰기로 첫 기록을 넣어주세요" 같은 빈 상태 문구를 보여준다.
- 폰에서도 보이도록 좁은 화면에서는 칸들을 세로로 쌓는다(대시보드가 홈 화면 앱으로도 쓰인다).

시안: `.superpowers/brainstorm/…/content/assets-page.html`(전체), `assets-composition-v2.html`(자산 구성 A안, 입금·지출 차트, 월별/연별 전환). 시안 파일은 git에 올라가지 않는 로컬 파일이다.

## 6. 섹션별 내용 (위에서 아래 순서)

### 6.1 한눈에 (첫 섹션)
가로로 다섯 칸을 둔다. 총자산은 가장 크게, 노란색으로 보여준다.
1. 총자산
2. 현금 (부동산 제외)
3. 부동산
4. 전달 대비 증감 (금액과 %. *(설계자 판단)* 늘면 빨강, 줄면 파랑. 한국 증시 색 관례를 따름)
5. 은퇴준비율 (%)

제목 옆에 "2026년 10월 기준"처럼 기준월을 표시한다.

### 6.2 자산 구성 — **A안으로 확정**
부동산이 80~90%라 한 차트에 같이 그리면 현금이 안 보인다. 그래서 둘로 나눈다.
- **위**: 얇은 가로 막대 하나로 부동산과 현금의 비율만 보여준다. 양쪽 끝에 금액과 %를 쓴다.
- **아래**: 현금을 100%로 놓은 도넛 차트. 조각은 계좌별로 나누고, 본인 계좌는 파랑 계열, 배우자 계좌는 초록 계열로 묶는다. 가운데에 현금 총액을 쓴다.
- 도넛 옆 범례: 그룹(본인 / 배우자)마다 합계와 현금 대비 %를 쓰고, 그 아래 계좌별 금액을 쓴다.
- 계좌 이름과 개수는 사용자가 입력한 그대로 따른다. 예시로 든 국내주식·해외주식(본인), 퇴직연금·CMA·연금(배우자)은 고정값이 아니다.

**같은 섹션 아래쪽: 입금·지출 막대차트**
- 기간마다 막대 두 개를 나란히 세운다. **입금은 빨강, 지출은 파랑.** 막대 위에 금액을 쓴다.
- 오른쪽 위에 "월별 / 연별" 전환 버튼을 둔다.
  - 월별: 달마다 그달 입금·지출.
  - 연별: 그해 기록된 달의 입금·지출을 더한 값. 12월까지 다 채워지지 않은 해는 "2026 (10개월)"처럼 진행 중임을 표시한다.

### 6.3 총자산 추이
- 선 차트. 노란 선은 총자산, 초록 선은 현금.
- "월별 / 연별" 전환:
  - 월별: 달마다 입력한 잔액을 그대로 찍는다(잔액이므로 더하지 않는다).
  - 연별: 해마다 마지막으로 기록된 달의 잔액을 찍는다. 올해는 지금까지의 최신 값이다.
- 점에 마우스를 올리거나 누르면 그 시점의 총자산, 현금, 부동산을 보여준다.
- *(설계자 판단)* 월별 보기에서 기록이 너무 많아지면 최근 24개월만 보여주고 옆으로 넘겨 보게 해도 된다.

### 6.4 메모
- 자유롭게 쓰는 칸 하나. 대시보드 자유노트처럼 입력하면 자동 저장되고 저장 상태를 작게 표시한다.
- *(설계자 판단)* 글자만 받는다. 이미지 붙여넣기는 이번 범위에서 뺀다.

### 6.5 은퇴준비도
- 진행 막대: 현재 현금 / 목표 20억.
- 숫자: "현금 3억 8,000만 / 목표 20억 · 19.0% 달성 · 남은 금액 16억 2,000만".
- 목표에 들어간 지출 항목(월생활비, 의료비, 여행비, 취미·운동비, 세금, 기타 비상금)은 작은 이름표로만 보여준다.

### 6.6 AI 점검
- 페이지에서 직접 AI를 부르지 않는다. 사용자가 Claude에게 "자산 점검해줘"라고 하면 Claude가 Supabase의 자산 기록을 읽고, 20년 차 은퇴설계 전문가 관점에서 분석과 짧은 컨설팅을 써서 Supabase에 저장한다. 페이지는 저장된 글을 보여주기만 한다. 채널기획노트에서 이미 쓰는 방식과 같다.
- 페이지에는 마지막 점검 날짜, 기준월, 본문(진단 / 조언)을 보여준다. 점검 글이 아직 없으면 "Claude에게 '자산 점검해줘'라고 말하면 여기에 분석이 올라와요"라고 안내한다.
- 은퇴 시점과 나이는 받지 않는다. 분석은 기록만으로 한다: 현금 비중과 부동산 쏠림, 월별 현금 증가 속도, 입금 대비 지출 비율(저축률), 계좌 구성, 지금 속도라면 20억까지 몇 년이 걸리는지 등.
- *(설계자 판단)* 점검 글은 매번 덮어쓰지 않고 날짜별로 쌓는다. 페이지에는 최신 글을 보여주고, 지난 점검은 접어서 볼 수 있게 한다.
- 구현이 끝나면 Claude가 다음 대화에서 이 작업을 어떻게 하는지 알 수 있게 메모리(또는 스킬)에 남긴다. 읽을 테이블, 쓸 테이블, 글 형식을 적는다.

## 7. 이번달 가계부쓰기 팝업

**입력 칸**
- 월 선택 (YYYY-MM)
- 이달 입금, 이달 지출
- 현 부동산 시세
- 본인 주식계좌: 계좌마다 이름 + 잔액. "＋ 계좌 추가"와 줄마다 "✕"로 추가·삭제한다.
- 배우자 주식계좌: 위와 같다.
- 본인 합계, 배우자 합계: 입력하는 대로 자동 계산해서 보여준다(입력 칸이 아니다).
- 취소 / 저장.

**동작**
- 저장하면 그 달 기록을 저장하고 페이지 전체를 다시 그린다.
- 이미 기록된 달을 고르면 그 달 값이 채워지고, 저장하면 덮어쓴다.
- *(설계자 판단)* 기록이 없는 새 달을 고르면 가장 최근 기록의 부동산 시세와 계좌 목록·잔액을 미리 채운다. 입금·지출은 빈칸으로 둔다. 바뀐 숫자만 고치면 된다.
- 팝업을 처음 열면 월 선택의 기본값은 이번 달이다.
- *(설계자 판단)* 기록된 달을 지울 수 있게 팝업에 "이 달 기록 삭제"를 둔다(확인을 한 번 더 받는다).
- 계좌를 삭제해도 지난달 기록에는 영향이 없다. 계좌 목록은 달마다 따로 저장된다.

## 8. 저장 (Supabase)

- 기존 프로젝트(`mwpyzhshhrzpmdmmuhzb`)에 새 테이블을 만든다. 보안 규칙은 기존 테이블과 똑같이 한다. 2026-10-23에 확인한 기존 상태는 다음과 같다.
  - 로그인 계정은 하나다(auth.users 1명). 부부가 같은 계정으로 본다.
  - 기존 테이블 `calendar_events`, `entries`, `study_notes`, `timeline`에는 모두 `owner only` 정책 하나가 있다. 대상은 `authenticated`, 동작은 ALL이고, 조건은 `using`과 `with check` 모두 `(auth.jwt() ->> 'email') = 'evadslr@gmail.com'`이다.
  - 새 테이블도 RLS를 켜고 같은 정책을 건다. 그러면 누가 가입을 해서 로그인하더라도 이 이메일이 아니면 읽을 수 없다. 테이블에 사용자(소유자) 열은 필요 없다.
  - *(설계자 판단)* 나중에 배우자가 따로 계정을 만들면 정책 조건에 그 이메일만 추가하면 된다.
- 필요한 데이터:
  - **월 기록**: 월(키), 입금, 지출, 부동산 시세, 본인 계좌 목록(이름·잔액·순서), 배우자 계좌 목록, 수정 시각. 계좌 목록을 JSON 열로 둘지, 계좌 테이블을 따로 둘지는 설계자가 정한다.
  - **메모**: 글 하나. 기존 `study_notes`에 새 id(예: `assetnote`)로 넣는 방식도 된다.
  - **AI 점검**: 날짜, 기준월, 본문.
- 합계, 총자산, 현금, 비율은 저장하지 않고 화면에서 계산한다.

## 9. 백업

- **사용자 결정: 주식대시보드와 자산관리를 한 번에 함께 백업한다.** 대시보드의 기존 "⬇ 백업"(`backupAll()`)을 넓혀서, 지금 담는 주식 데이터(timeline, entries, study_notes, 이미지)에 자산 데이터(월 기록, 메모, AI 점검)를 더해 **HTML 파일 하나**로 내려받는다.
- 그 파일을 열면 주식 부분과 자산 부분을 각각 표로 읽을 수 있다. 로그인 후 "복원"을 한 번 누르면 둘 다 Supabase에 다시 넣는다.
- 자산관리 페이지 상단의 "⬇ 백업"도 같은 함수를 불러 똑같은 파일을 만든다.
- 파일 이름: 기존 `주식대시보드_백업_YYYY-MM-DD.html`을 그대로 쓴다. *(설계자 판단)* 내용이 늘어난 것을 알 수 있게 파일 안 제목에 "주식 + 자산"을 표시한다.
- 지금 있는 예전 백업 파일(자산 데이터 없음)로 복원해도 오류 없이 주식 데이터만 복원되어야 한다.

## 10. 설계자에게 맡기는 것

- 차트를 그리는 방식. 대시보드는 금리 차트에 uPlot을 이미 쓰고 있다. 도넛과 막대는 SVG로 직접 그려도 된다.
- 테이블과 열 이름, 계좌 목록 저장 구조.
- 코드 배치(`assets.html` 한 파일에 둘지, 공통 코드를 나눌지).
- 세부 간격, 글자 크기, 정확한 색 값. 단, 위에서 정한 색(입금 빨강·지출 파랑, 본인 파랑 계열·배우자 초록 계열, 총자산 노랑·현금 초록 선, 노란 버튼)은 지킨다.

## 11. 작업 방식 메모
